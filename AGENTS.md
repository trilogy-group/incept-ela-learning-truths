# Assessing this repository

Read README.md and IDEAS.md, then PERFECT-QUESTION.md and GENERATING.md. Follow a statement into its JSON record in learnings/; inspect its scope, status, evidence and against field. The public research is not a qualified evaluator or a measured learner outcome.

Read contract/README.md for the shared formats and reference example. It contains author material and intended answers, not private challenge labels. The reference’s extracted units include paragraph subchecks and guided tasks, not forty independent mastery measurements.

Run `python3 run.py`. Before committing, run `python3 scripts/check.py` and `python3 contract/scripts/check.py` separately; both must exit 0. The first check may require registered local research sources. The contract check states whether external Git source comparison ran; matching a committed fixture hash is a different claim.

Useful feedback identifies a specific unsupported, contradicted, overly broad or missing statement, gives its record/file, and supplies the evidence or counterexample. Also check whether the shared format preserves the actual learner context and whether an example’s intended operation fits its response.

Both halves can read this public library and contract. Keep evaluator implementation and development cases in the evaluator repository, outside generator inputs and shared exports. Independent qualification labels and sealed holdouts belong in separate restricted storage, never in these public repositories. Review each half in a separate context; public visibility does not enforce blindness. Preserve the original source pin when reviewing the reference.

Use CLAUDE.md for edits to records, pages or research. Do not alter registered source repositories, call models, start research runs or publish anything as part of an assessment. Keep credentials and personal metadata out of the repository. Use the machine-wide work registry when available.
